# Проект OzonCardAI

## Название

**OzonCardAI** — профессиональное настольное приложение для Linux (Ubuntu), предназначенное для автоматизации подготовки карточек товаров Ozon на основе существующих товаров продавца на Wildberries.

## Назначение

Цель проекта — снизить объем ручной работы продавца при переносе и адаптации товарных карточек между маркетплейсами. Приложение должно помогать получать исходные данные из Wildberries, передавать их в AI-модуль для подготовки контента и создавать черновики карточек через Ozon Seller API после проверки пользователем.

На текущем этапе реализуется фундамент интерфейса и структуры проекта. Интеграции с внешними API, авторизация, база данных и AI-логика пока не реализуются.

## Используемые технологии

- **Python 3.12+** — основной язык разработки.
- **PyQt6** — графический интерфейс desktop-приложения.
- **QMainWindow** — базовая структура главного окна.
- **QListWidget** — боковая навигация.
- **QStackedWidget** — переключаемая рабочая область.
- **QSS** — единый стиль интерфейса без сторонних UI-библиотек.
- **Git и GitHub** — контроль версий, ревью и дальнейшая совместная разработка.

## Текущая архитектура

Проект уже разделен на независимые слои и пакеты, чтобы его можно было расширять без переписывания основного интерфейса:

- точка входа запускает приложение и не содержит бизнес-логики;
- главное окно отвечает за компоновку интерфейса, меню, toolbar, навигацию и переключение страниц;
- страницы интерфейса вынесены в отдельный модуль;
- стили вынесены в отдельный QSS-модуль;
- каталоги для API, сервисов, моделей, утилит и workers подготовлены для будущих этапов.

## Назначение каталогов

### `app/`

Основной Python-пакет приложения. Здесь размещается весь код, относящийся к продукту.

### `app/api/`

Будущий слой клиентов внешних API. В дальнейшем здесь должны появиться отдельные клиенты для Wildberries API и Ozon Seller API.

### `app/models/`

Будущие доменные модели и структуры данных: товар Wildberries, карточка Ozon, результат AI-генерации, операция импорта и другие сущности.

### `app/services/`

Будущий слой бизнес-логики. Здесь должны располагаться сервисы, которые координируют API-клиенты, модели, генерацию карточек и подготовку данных для интерфейса.

### `app/ui/`

Слой пользовательского интерфейса на PyQt6. Сейчас содержит главное окно, фабрики страниц и общий QSS-стиль приложения.

### `app/utils/`

Будущие вспомогательные функции, не относящиеся напрямую к UI или бизнес-логике.

### `app/workers/`

Будущее место для фоновых задач и worker-классов. Пока многопоточность не реализуется.

### `assets/`

Будущие статические ресурсы приложения: иконки, изображения, логотипы и другие UI-ассеты.

### `cache/`

Будущий каталог временных данных приложения. Не должен использоваться как постоянное хранилище бизнес-данных.

### `logs/`

Будущий каталог логов приложения.

### `tests/`

Каталог для автоматических тестов.

## Будущая архитектура приложения

В дальнейшем проект должен развиваться как модульное desktop-приложение со строгим разделением ответственности:

- **UI-слой** отображает данные, принимает действия пользователя и не содержит сетевой или AI-логики.
- **Service-слой** управляет сценариями: импорт товаров, подготовка данных, генерация карточек, создание черновиков.
- **API-слой** содержит изолированные клиенты Wildberries, Ozon и AI-провайдеров.
- **Model-слой** описывает доменные данные и DTO для обмена между слоями.
- **Worker-слой** выполняет долгие операции без блокировки интерфейса.
- **Utils-слой** содержит только небольшие переиспользуемые вспомогательные функции.

## Целевой процесс работы приложения

1. **Wildberries**
   - Пользователь подключает аккаунт Wildberries через официальный API.
   - Приложение получает список товаров, описания, характеристики и другую доступную информацию.
   - Пользователь выбирает товары для переноса или обработки.

2. **ИИ**
   - Выбранные данные передаются в AI-провайдер: Mistral, OpenRouter, Gemini, OpenAI или другой LLM.
   - AI анализирует исходные данные и генерирует контент, адаптированный под Ozon.
   - Формируются название, описание, SEO, ключевые слова, характеристики и рекомендации по заполнению атрибутов.

3. **Ozon**
   - Подготовленные данные сопоставляются с требованиями Ozon Seller API.
   - Пользователь проверяет результат перед отправкой.
   - Приложение создает черновик карточки товара через официальный API.

4. **Черновики**
   - Созданные черновики отображаются пользователю.
   - Пользователь видит статус, возможные ошибки и рекомендации по исправлению.

5. **Публикация**
   - Финальная публикация остается под контролем пользователя.
   - Приложение должно помогать подготовить карточку, но не скрывать критически важные действия от продавца.
